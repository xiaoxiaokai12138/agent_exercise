# 需求与范围

内容运营需要把待处理素材整理成一份可确认的发布排期。系统逐项说明素材能否进入草稿、存在什么风险、原时段是否有冲突，以及仍需要用户确认什么。

## 输入与输出

- 请求 JSON 中的 `materials` 是非空列表。每项有 `material_id` 和硬性 `requested_at`，时间按上海时间解释。
- `--catalog` 指定合成素材元数据及审核规则。每份元数据可包含标题、渠道、负责人和授权确认状态。渠道是排期必需字段；授权确认状态使用 JSON 布尔值。缺失或无法使用的必需字段由审核工具列出。`--schedule` 指定各渠道可排时段与已有占用记录。
- 输出含素材审核状态、风险规则及原因、缺失字段、冲突来源、建议时段、待确认项、草稿状态和任务状态。整批均处理完成时，顶层为 `complete`，其余为 `incomplete`，具体原因见各素材。

## 成功标准

| 验收点 | 预期行为 |
| --- | --- |
| 正常排期 | 审核通过且原时段空闲，保存草稿并返回 ID |
| 素材信息缺失 | 列出缺失素材或字段，请求补充 |
| 规则风险 | 给出阻断规则和风险原因，结束该项处理 |
| 时段冲突 | 查询备选时段，保留原始时间要求，等待确认 |
| 重复提交 | 同一素材、渠道、时段返回同一草稿 ID，数据库保留一条 |
| 保存失败 | 返回草稿失败和未完成状态，给出失败码 |

模型每轮接收工具结果并选择后续动作。默认每项素材最多 8 次模型决策，达到上限时返回 `incomplete` 和 `step_limit`。批次按请求顺序处理，同渠道同一时刻只允许一个草稿占位。

## 原型边界

排期以离散时刻表示，备选范围为同一天更晚的可用时段，最多三项。改期确认通过提交一个显式包含新时间的请求表达。项目范围止于本地排期草稿。
