# 方案与取舍

## 模型与工具循环

CLI 逐项传入原始请求。Agent 把最近一次工具观察与历史观察交给 Ollama。模型返回一个结构化动作及一句公开决策依据。Agent 校验动作、绑定参数、执行工具，再把观察交回模型。模型也可选择一个结束动作，其结论须能由已有观察验证。每次模型决策都计入步数，包括结束动作和被拒绝的动作。

| 工具 | 输入来源 | 返回内容 |
| --- | --- | --- |
| `read_material` | 请求的素材 ID | 元数据或素材不存在 |
| `check_rules` | 读取结果中的元数据 | 审核结果、缺失字段、风险规则 |
| `check_slot` | 请求时段与素材渠道 | 可用、已有排期冲突或其他草稿占用 |
| `find_alternatives` | 同一素材和冲突时段 | 同渠道当天更晚的可用时段 |
| `save_draft` | 审核通过的素材和原请求时段 | 写入、复用、冲突或工具错误 |

可执行动作是一个固定集合。正常和冲突场景都把 `check_slot` 的实际返回交给模型，随后由模型选择保存或查找备选。Mock 模式用固定映射替代模型。真实模式连接 Ollama `/api/chat`，用 JSON Schema 约束动作格式，运行时仍校验动作与证据。

## 确认和写入

保存的前置条件是审核通过且原请求时段可用。写入参数直接取原始请求，备选查询的返回只用于建议和待确认项。模型选择缺乏证据的结束动作时，程序返回 `guard_rejected`，模型可以在剩余预算内重新选择。遇到同一渠道时段的竞争，保存工具在 SQLite 写事务内重新检查占位。

SQLite 用 `(channel, slot)` 唯一约束占位。写事务发现同一素材的既有记录时返回原 ID，发现另一素材的记录时返回冲突。批次内每个草稿独立提交。若最后一步用完预算，输出仍报告已落库的草稿状态，整体任务标为未完成。

## 工程取舍

使用 Python 标准库、SQLite 和本地 Ollama。显式循环便于评审逐步核对模型决策。合成素材和离散时段让权限、冲突和幂等都可以用小数据直接验证。已有排期来自只读 JSON，SQLite 只维护本地草稿；原型以本次运行加载的已有排期为准。
